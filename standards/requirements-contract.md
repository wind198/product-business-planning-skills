# Product requirements and architecture handoff

SRS/PRD owns what product users need and how acceptance will be judged, not detailed architecture decisions. Use IDs `SEG-`, `JOB-`, `OPP-`, `HYP-`, `EXP-`, `CAP-`, `FEAT-`, `FR-`, `NFR-`, `DEC-`, `METRIC-` and `EV-`. Link `customer segment → job/problem → value proposition → feature → FR/NFR → acceptance evidence`. Include scope/non-goals, actors, business rules, exceptional flows, data/privacy expectations, nonfunctional expectations and testable criteria.

Hand off requirements and business constraints to the separate L1/L2 solution architecture framework. That framework returns technical feasibility, risks, dependencies and cost impact. Never silently substitute architecture choices for product requirements.
